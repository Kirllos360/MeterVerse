# P12-02-05 — CORRELATION / CAUSATION / TRACEABILITY

## 1. Enterprise identifiers (§9)
| ID | Generated by | Authority | Propagates |
|----|--------------|-----------|------------|
| requestId | API middleware (per HTTP request) | server (or client-provided, validated UUID) | request → service → DB → response header |
| correlationId | API middleware / dispatcher (per business transaction) | **server-authoritative** (client header accepted only if valid UUID, else replaced) | frontend → API → service → outbox → consumer → webhook → audit |
| causationId | parent event (consumer sets when emitting child) | server | child event → parent linkage |
| eventId | producer (outbox insert) | server | event → delivery → consumer |
| commandId | client (explicit, optional) | client (validated) | idempotency key derivation |
| idempotencyKey | sha256(scope:area:op:clientKey) | derived | idempotency record |
| traceId/spanId | reserved (future OTEL) | server | logging |

## 2. Propagation chain (§9)
```
Browser → FE (generate/forward X-Correlation-ID)
  → API middleware (create requestId, ensure correlationId)
  → service → prisma (outbox row carries correlationId)
  → dispatcher → consumer (same correlationId + causationId=parent eventId)
  → external integration (X-Correlation-ID header)
  → callback/webhook (echo correlationId)
  → AuditEntry (correlationId column)
```

## 3. Spoofing prevention (§9)
- **Server-authoritative:** correlationId is validated (UUID) or regenerated at the API boundary — a client cannot forge a trusted trace chain.
- causationId is server-set only (consumer).
- idempotencyKey is derived server-side; client cannot choose a key in another tenant (areaId bound).

## 4. Logging
- Every log line includes requestId + correlationId (+ service). Structured JSON via existing logger.
- AuditEntry gains `correlationId` column (migration).

## 5. Privacy
- correlationId is opaque (UUID), no PII. Payload metadata must NOT include PII in event fields beyond what domain requires; sensitive payloads flagged (see 07_EVENT_SECURITY).

## 6. Persistence (CorrelationContext)
- Not persisted as a standalone table by default (correlationId column on OutboxEvent + AuditEntry suffices).
- If cross-service correlation analytics needed → future CorrelationContext view from outbox+audit (documented, not created).
